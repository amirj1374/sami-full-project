# راهنمای نسخه آزمایشی مهاجرت حسابداری آسان

این بسته فقط برای آزمون فایل‌های واقعی مشتری است. همه داده‌ها در جداول
`legacy_*` و فضای فایل اختصاصی همین محیط نگهداری می‌شوند. این نسخه هیچ مشتری،
کالا، انبار، موجودی، فروش، سند حسابداری، بانک یا چکی را در داده‌های اصلی SAMI
ایجاد یا Overwrite نمی‌کند. **Final Import در این نسخه وجود ندارد و مسدود است.**

## پیش‌نیاز

- Windows 10/11 با Docker Desktop و Linux containers
- Docker Compose و Buildx فعال
- اینترنت برای دریافت imageهای پایه در اولین Build
- حداقل ۸ گیگابایت RAM و ۱۵ گیگابایت فضای خالی

فایل ZIP را در یک مسیر محلی کوتاه و بدون دسترسی عمومی Extract کنید. فایل‌های
واقعی آسان را داخل پوشه پروژه کپی نکنید؛ آن‌ها را مستقیماً از صفحه Upload انتخاب
کنید.

## شروع

PowerShell را در ریشه بسته باز کنید و اجرا کنید:

```powershell
.\scripts\asan-customer-validation.ps1 -Mode Start
```

در اولین اجرا imageها Build می‌شوند و ممکن است چند دقیقه طول بکشد. پس از Healthy
شدن هر سه سرویس، نشانی برنامه و مسیر فایل Credentials نمایش داده می‌شود. فایل
Credentials و فایل `.env.customer-validation` محرمانه‌اند و نباید برای شخص دیگری
ارسال شوند.

## سناریوی آزمون مشتری

1. با حساب محلی درج‌شده در فایل Credentials وارد شوید.
2. از منوی «ورود و مقایسه داده‌های قدیمی» یک بسته مهاجرت بسازید.
3. هر گزارش واقعی XLSX را جداگانه Upload کنید.
4. برای هر فایل ابتدا «تحلیل» و سپس «ثبت در ناحیه واسط» را بزنید.
5. اگر سطح دفتر با اطمینان پایین تشخیص داده شد، نوع دفتر کل، معین یا تفصیلی را
   با اطلاعات خود مشتری تأیید کنید.
6. پس از تکمیل همه فایل‌ها «اجرای تطبیق» را بزنید.
7. شمار ردیف‌های روزنامه، تراز آزمایشی و چک، جمع بدهکار/بستانکار و هشدارها را با
   گزارش‌های آسان تطبیق دهید.
8. دکمه «دریافت گزارش اعتبارسنجی» را بزنید. این JSON شامل رکورد خام یا نام فایل
   نیست و برای بررسی فنی قابل ارسال است.
9. در PowerShell اجرا کنید:

```powershell
.\scripts\asan-customer-validation.ps1 -Mode Evidence
```

فقط این دو فایل را برای تیم فنی ارسال کنید:

- `asan-customer-validation-<id>.json` که مرورگر دانلود کرده است؛
- `customer-validation-artifacts/customer-validation-runtime-evidence.json`.

فایل XLSX/RAR/ZIP، Credentials، `.env`، database volume، screenshot حاوی داده و
logها را ارسال نکنید مگر با مجوز و کانال امن جداگانه.

## توقف و ادامه

برای توقف امن:

```powershell
.\scripts\asan-customer-validation.ps1 -Mode Stop
```

این فرمان containerها و network همین پروژه آزمایشی را حذف می‌کند ولی volumeهای
دیتابیس و Upload را حفظ می‌کند تا اجرای بعدی ادامه همان آزمون باشد. برای مشاهده
وضعیت از `-Mode Status` استفاده کنید. حذف volumeها عمداً خودکار نشده است؛ اگر
مشتری پس از پایان آزمون خواست داده آزمایشی را پاک کند، ابتدا تأیید کتبی بگیرید و
فقط volumeهای دارای پیشوند `sami-asan-customer-validation` را هدف قرار دهید.

## نتیجه قابل قبول

- PostgreSQL، backend و frontend همگی `healthy` باشند.
- `/health` از مسیر nginx پاسخ ۲۰۰ بدهد و `/api` به backend Proxy شود.
- همه فایل‌ها بدون OOM در Staging ثبت شوند.
- `source_record_count` و `imported_record_count` هر dataset برابر باشند.
- اختلاف بدهکار و بستانکار و کنترل‌های تراز/چک با خروجی آسان توضیح‌پذیر باشند.
- `rawRecordsIncluded=false`، `canonicalWrites=0` و
  `finalImportAvailable=false` در گزارش خروجی باقی بمانند.

این نتیجه فقط قابلیت پردازش فایل واقعی و تطبیق Staging را تأیید می‌کند؛ مجوز
Production Migration یا Final Import نیست.
